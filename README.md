# pagh-api — пользовательский API для pagh-riscv

Локальный репозиторий (пока не опубликован). Один слой, на котором стоят
инструменты из `../pagh-tools`: syscall-обёртки, типы, рантайм-хуки и
документированный контракт «что ядро обязано предоставить userland'у».

## Что здесь будет

1. **`libpagh`** — `no_std`-крейт без внешних зависимостей:
   - `sys` — сырые `ecall`-обёртки с номерами Linux/RISC-V (`read`, `write`,
     `openat`, `close`, `lseek`, `exit`, `sched_yield`, `getpid`, `mmap`, `brk`,
     `clock_gettime`, `poll`, `socket`/`connect`/`send`/`recv` — по мере того,
     как ядро их реализует);
   - `errno` — ошибки в стиле POSIX, конвертация из отрицательного результата;
   - `io` — `Read`/`Write`-подобные трейты поверх fd;
   - `net` — минимальный сокет-API (TCP-клиент, потом UDP) поверх `sys`;
   - `fs` — пути/каталоги поверх `openat`/`getdents`;
   - `alloc`-хук — аллокатор поверх `brk`/`mmap` (когда ядро даст);
   - `start` — crt0/`_start`, паника, `print!`/`println!` на `write(1,…)`.
2. **Спецификация ABI** (`docs/abi.md`) — точный контракт с ядром:
   регистры `ecall`, таблица номеров, коды ошибок, модель указателей,
   выравнивание, что разрешено в U-mode. Ядро и этот крейт обязаны совпадать
   (тест-константы сверяются в CI).
3. **Контракт для ядра** — какие syscall'ы в каком порядке надо добавить
   pagh-riscv, чтобы заработали Rust-рантайм и инструменты: mmap/brk, futex,
   poll, sockets, time, threads. Это вход в следующий мильстоун ядра.

## Как сюда попадают инструменты

`pagh-tools` зависит от `pagh-api` (path-зависимость, пока локально) и **не
копирует** libc/curl/ripgrep: каждая программа пишется под этот API и
проверяется живым запуском в QEMU.
